# RAGルーター実証実験


仕事の依頼を「軽いモデルで十分か／上位モデルを出すべきか」で振り分ける、小さなローカルLLMルーターの実証実験です。


振り分けの判断材料として、過去の作業履歴をベクトル検索で参照する条件（RAG）と、参照しない条件を比較しました。


Zenn記事「[「慣れた」ローカルLLMがモデルを選ぶ —— 実務のコスパ評価とRAGルーターの構想](https://zenn.dev/7thcode/articles/25d5a8b0e8c4d5)」（Zennfes Autumn 2026「私の考えるハイブリッドLLM～実践と構想～」構想部門）の第6節の実験コードです。


## 実行方法


前提：[Ollama](https://ollama.com/) が起動していること、Node.js 18以上。


```bash
ollama pull gpt-oss:20b
ollama pull nomic-embed-text
node router.mjs gpt-oss:20b nomic-embed-text
```


引数を省略すると、Ollamaに入っているモデルから自動で選びます。結果は標準出力と `results.md` に保存されます。


## ファイル


- `router.mjs` — 実験本体（依存パッケージなし、Ollama APIのみ使用）
- `history.json` — 履歴データ36件（バグ修正・コードレビュー・要約・調査・分類抽出・エージェント作業の5パターン）。**実ログではなく、典型例から作ったサンプルデータ**です
- `tests.json` — 正解ラベル付きテスト20件


## 結果（M1 MacBook Pro / メモリ64GB）


| ルーター | 条件 | 一致率 | 平均判定時間 |
|---|---|---|---|
| gpt-oss:20b | 履歴参照あり（RAG） | 17/20（85%） | 3.68秒 |
| gpt-oss:20b | 履歴参照なし | 17/20（85%） | 2.61秒 |
| qwen2.5-coder:7b | 履歴参照あり（RAG） | 15/20（75%） | 1.70秒 |
| qwen2.5-coder:7b | 履歴参照なし | 15/20（75%） | 1.05秒 |


履歴参照による一致率の向上は見られませんでした。考察は記事の第6節に書いています。要点は「RAGが効くのは、自分の履歴が世間の典型から外れている部分であり、測るには実ログが要る」ということです。
